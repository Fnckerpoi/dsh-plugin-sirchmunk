# 七模型交付审阅门禁

本清单是验收条件，不代表已通过。只建模 DSH 插件集成，不构建独立业务应用。

## 结构与引用

- 七个 YAML 严格解析，无重复键；manifest 文件指向有效。
- model_type：OBJECT、BEHAVIOR、RULE、ACTOR、FLOW、REPORT、UI。
- 核心结构遵循 ontology_modeling_framework_v9.md；适配项明确使用 x 扩展。
- 稳定 ID 唯一，所有引用存在且类型正确。
- 属性规则归 refRules，聚合约束归 invariants，跨对象判定归 M3。
- M2 ownerEntity 指向 M1 ID；所有 USER_ACTION 在 MU 有操作入口。
- 七项 REP/Q 双向一对一，禁止重复同义 QUERY。
- M5 权限绑定行为；MU 操作集合与权限矩阵一致。
- M6 活动可达结束，引用存在，子流程无环。
- syncTriggers 仅跨独立聚合同步调用；不能用于同对象检查、格式转换、视图刷新或异步探测。

## 业务边界

- 检索整体委托 Sirchmunk 本地模型；禁止自动降级 DSH 文件扫描。
- 页面打开、筛选、刷新、导出不调用模型。
- 配置/运行时/外部权威数据分层；不生成第二份知识库或检索业务表。
- 不改 Sirchmunk API、CLI、MCP、数据库或聚类算法。
- 不建第二套账号系统；Host 鉴权不足时关闭管理写功能。
- 普通用户状态摘要不得泄漏管理员地址、凭据或诊断信息。
- 图谱示例不冒充真实内容，关系类型沿用后端值。
- 写操作不自动重试；超时标记结果未知；刷新失败不撤销已完成写入。
- 聚类删除仅管理员、输入名称确认、调用后端既有 API。
- 历史共享只读，无 Chat、删除、清空和历史导出。
- 图谱 JSON/PNG/SVG 导出按当前视图/全部可见范围分权；布局不持久化。
- 环境设置只读；非敏感 UI 设置可编辑且不联动 DSH 全局设置。
- 无审批流、上传、集合管理或成本对比报表。

## 实施门控，不得伪称已验证

- DSH 插件入口、Host 鉴权、凭据与 MCP 隔离治理的实际支持。
- 容器 MCP 与 HTTP 是否使用同实例、同模型和工作数据。
- 实际 MCP Schema/返回格式、历史覆盖与 API 分页过滤能力。
- HTTP 失败是否阻断独立 MCP，若基线冲突须明确记录。
- 运行中请求遇到停用的策略、取消支持、超时和重试上限不得凭空指定。

静态一致性通过不等于插件运行或外部联调通过。主代理维护本清单；子代理维护模型文件。
