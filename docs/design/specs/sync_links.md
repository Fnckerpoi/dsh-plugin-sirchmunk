# 阶段三：跨对象联动确认记录

状态：用户已确认本阶段问题 1～3 均按 AI 建议。本文为需求草稿，不表示代码已实现。

## 已确认决策

1. 连接配置通过安全及格式校验即可保存。健康检查随后异步执行，失败不回滚配置。
2. 插件自身写操作明确成功后，重新读取受影响的数据。不持续轮询其他客户端引发的变化，提供手动刷新。
3. 停用或移除连接后，阻止新委托、管理 API 请求以及通过该集成入口打开历史来源文件。历史记录保留并标记不可访问。

## 联动候选与边界

- LINK-01：地址或凭据变化使健康状态失效，随后检查；保存与探测不是跨系统原子事务。
- LINK-02：健康检查影响页面能力展示；HTTP 与 MCP 是独立通道，HTTP 不可用是否阻断独立 MCP 通道尚需明确，不视为已确认的技术事实。
- LINK-03：保存绑定后验证 MCP 工具，握手失败与 Schema 不兼容分别标记。
- LINK-04：按已确认决策阻断集成入口；不得声称插件可以撤销 DSH 其他工具的独立文件权限。实际 Host 门控能力待核验。
- LINK-05：保留实际 MCP 返回的答案与来源；返回内容可能是文本，不强制假设为 JSON。检索完成不等于结果解析成功。
- LINK-06：以后端协议定义的成功结果为准，不仅依据 HTTP 200。刷新失败不回滚后端已完成操作，应标注展示可能过期。
- LINK-07：首期只允许非敏感 UI 设置修改；不包含模型、API Key、搜索目录修改。仅按实际影响刷新，不虚构环境配置变更。
