# 七模型建模输入与适配边界

本文件补充摘要需求文档缺失的附录 C 映射，不改变已确认业务范围。

## 输入优先顺序
1. 用户逐阶段明确确认及后续修订。
2. `.dsh-plugin-sirchmunk/` 分阶段基线。
3. 主需求文档是摘要，不覆盖更具体条件。
4. `ontology_modeling_framework_v9.md` 控制核心结构，但不能把外部集成改造成单体业务库。

## 确定性映射
- OBJ-01～03 → M1 插件配置对象；凭据只存引用，无 Chat 入口。
- OBJ-04～06 → M1 运行时轨迹/值对象；不新建检索业务库。
- OBJ-07～08、历史、监控、设置 → M1 外部投影；Sirchmunk 权威。
- FUNC-01～17 → M2；R-01～08 → M3；PROC-01/02 → M6，无审批。
- 使用者/管理员 → M5 内部角色；自动主体不提权；Sirchmunk Agent 是外部主体扩展。
- REP/Q 01～07 → M7/M2 双向一对一；UI-01～08 → MU。

## 精确口径
- 历史只读共享，无续聊、删除、清空、导出。
- 监控刷新不测试模型；失败可保留上次数据并标记过期。
- 环境配置只读；仅非敏感 UI 设置可编辑，且不联动 DSH。
- R-07 不是一律只读；聚类删除和 UI 设置修改受能力、权限门控。
- R-08 二次确认针对破坏性操作；删除聚类还须输入名称。
- 模式不固定 FAST；Agent 按复杂度选择并尊重用户指定。
- 图谱导出 JSON/PNG/SVG；当前视图使用者可用，全量仅管理员。
- 外部写结果未知不重试；成功后刷新失败不回滚。

## 适配与实施门控
V9 面向单体同步软件；本项目是外部集成。核心结构遵循 V9，外部权威、非持久化与异步探测使用文档化 `x_` 扩展，不承诺通用生成器可直接执行，也不复制 code-paas。

DSH Host 鉴权、MCP 拦截、作用域隔离、实际 Schema/字段、容器工作数据一致性、运行中停用/取消/超时/重试数值均待实施实测，不能伪称已确认。

只新增文档与 YAML，不修改代码、依赖、部署或连接；静态验证不等于运行联调。
