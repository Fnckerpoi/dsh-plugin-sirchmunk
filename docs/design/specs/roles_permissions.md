# 阶段六：角色与功能权限确认基线

状态：用户已确认问题 1～5 均按 AI 建议；仅为需求基线，未实现。

## 人工角色

- ROLE-01 Sirchmunk 使用者：使用 MCP 检索；查看图谱、聚类、共享 Sirchmunk 历史和基础运行状态；导出当前有权查看的过滤视图。
- ROLE-02 Sirchmunk 集成管理员：维护连接和 MCP 绑定；执行允许的知识管理动作；查看完整脱敏监控；修改首期允许的非敏感 UI 设置；导出全部可见图谱。

## 自动主体

- ROLE-03 DSH Agent：按当前用户权限执行 FUNC-07～FUNC-09，不绕过 Workspace、MCP 和文件权限。
- ROLE-04 Sirchmunk Agent：在外部系统中使用本地低成本模型执行完整检索，不拆分到 DSH M2。
- ROLE-05 DSH 插件运行时：执行安全访问、能力读取、裁剪、刷新及导出，不获得超越当前用户的业务权限。

## 已确认权限边界

- 不建立插件私有账号与角色系统，优先映射 DSH 既有身份和权限。
- 若 DSH Host 暂时不能可靠执行细粒度管理员鉴权，则关闭管理写功能，仅开放只读页面；禁止用前端隐藏按钮代替服务端权限控制。
- 普通使用者可查看当前连接暴露的共享 Sirchmunk 历史；后端不能区分用户时，不得称为“我的历史”。
- 知识聚类删除仅集成管理员可执行，并要求二次确认。
- 图谱默认导出当前过滤视图；“导出全部可见图谱”仅管理员可执行。
- 导出不包含密钥、凭据或未经授权的绝对路径，也不自动注入模型上下文。
- 检索来源引用不授予文件访问权；打开源文件仍受 DSH 原有权限治理。
- 无人工审批流。

## 行为权限摘要

使用者：FUNC-10、FUNC-11、FUNC-13、FUNC-14（基础）、Q-03、Q-04、Q-05、Q-06（基础），以及当前过滤视图导出。
管理员：FUNC-01～FUNC-06、FUNC-10～FUNC-15、Q-01～Q-07，以及受控的知识管理与全量可见图谱导出。
系统主体：DSH Agent 执行 FUNC-07～FUNC-09；运行时按人工行为代执行 HTTP 请求。

角色到行为关系是业务基线；实现前仍需核验 DSH 可用权限点和服务端门控机制。若不存在，按已确认降级为只读。
